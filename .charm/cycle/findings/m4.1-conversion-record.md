## What converts well

- **Prose, headings and structure.** All four samples read as legible articles at real pane
  widths: heading hierarchy survives intact (`why_anything.md` alone nests four levels,
  `##`–`####`), paragraphs and block quotes render normally, previously-linked phrases read
  as ordinary prose with no markdown link/URL syntax anywhere (M2.3's own acceptance,
  re-confirmed).
- **Tables.** `list_languages.md` and `major_arcana.md`'s content tables (`table.wikitable`)
  survive with correct column alignment and cell text; infobox/navbox/sidebar tables are
  gone, confirmed by grep for `table.infobox`/`navbox`/`sidebar` classes never surviving to
  the HTML stage that feeds conversion.
- **Chrome removal generally.** Navboxes, infoboxes, sidebars, portal bars, sister-project
  boxes (boxed and inline-template variants), edit-section links, reference-list sections,
  metadata tables and bare images are all gone with no visible hole — see the final selector
  list below.
- **Citation-like superscripts, including two shapes discovered late (M3.9, TRIAGE T1,
  D111).** Real reference markers (`[12]`), Wikipedia's maintenance-template family
  (`{{citation needed}}`, `{{clarification needed}}`, `{{dubious}}`, `{{disputed}}`) and the
  `{{rp|<page>}}` page-locator template are all gone with no leftover text. Worth recording
  for a future cycle: the maintenance-template family's visible `<sup>` carries **no**
  `typeof` at all — Parsoid's `typeof="mw:Transclusion"` marker instead lands on a
  preceding, invisible `<link rel="mw:PageProp/Category">` sharing the same `about` id — so
  it has to be matched by its `Inline-Template` CSS class, not a typeof selector like every
  other chrome category here; `{{rp}}`'s own `<sup>` *does* carry `typeof="mw:Transclusion"`
  directly (a real citation ref's typeof is always the compound
  `"mw:Transclusion mw:Extension/ref"`, so an exact-match selector on the bare value never
  collides with it). Neither shape failed a mechanical check while broken (each carries its
  own literal bracket text, or none), which is exactly why the original M3.2 A1–A4 pass and
  every mechanical re-check before M4.1's first pass missed both — only an eyeball read of a
  fresh regen caught them. `cmd/wikispike/htmldoc.go`'s `selectorCitationLikeSup` now unions
  all three shapes.
- **Maths (S6a experiment, M3.4 + its display/block addendum).** 61% of `E (mathematical
  constant)`'s 104 formula occurrences get a real Unicode approximation; the rest fall back
  to readable raw-TeX text; display-style formulas get their own fenced line. No mid-sentence
  gap remains anywhere in the sample. Full detail, tally and recommendation:
  `cycle/findings/maths-experiment.md`.
- **Images (S6a experiment, M3.5 + M3.5a).** Every figure in all four samples now shows a
  `` `[Image: <caption>]` `` placeholder (code-span-styled, via an actual `<code>` element so
  the html-to-markdown converter handles its own escaping) exactly where the image sat, with
  citation-superscript digits stripped from the caption text first. No sample's real content
  images needed the alt-text/filename fallback in practice, though the fallback chain is unit
  tested. Full detail and recommendation: `cycle/findings/images-experiment.md`.

## What converts badly, or not at all

- **Formula raw-TeX fallback (accepted, not a defect).** The 39% of `E (mathematical
  constant)`'s formulas termtex can't render on one line fall back to their raw LaTeX source
  (e.g. `e^{i\pi}+1=0`) sitting mid-sentence — legible as "formula-shaped" text, not pretty.
  Within SPEC's "ugly is acceptable, unreadable is a defect" bar; see
  `maths-experiment.md` for why a fuller fix (multi-line rendering for Parsoid's own
  display/block formulas) was already carried into this cycle rather than deferred.
- **Known limitations, documented and deliberately not fixed this cycle (unchanged from
  their own decisions, restated here for completeness):**
  - A half-open-interval idiom like `[0, 1)` would lose its `)` to `dropUnmatchedClosers`'s
    asymmetric closer-only repair (D107). Not observed in any S5 sample.
  - `dropUnmatchedClosers` tracks bracket depth across a whole flushed prose chunk, not per
    paragraph, so an earlier unmatched opener can mask a later genuinely-dangling closer
    (D108/TRIAGE T8-T9). Not observed in any S5 sample, only reproduced synthetically.
  - `sisterProjectInlineLine`'s match scope is the whole document, not just the
    External-links section named in M3.3b's own task text — accepted as a broadening, not a
    bug (D110).

## The selector/cleanup list as it ended up

Chrome removal (`cmd/wikispike/strip.go`'s `stripChromeInPlace`, in the order it runs):

1. `div.navbox` — navboxes.
2. `table.infobox, .infobox` — infoboxes.
3. `table.sidebar` — the second, distinct floated summary-box template (M2.2 gap, fixed
   directly).
4. `div.portal-bar, div.sistersitebox` — portal bars and boxed sister-project templates
   (M3.3a).
5. `removeSisterProjectInlineLines` — a text-pattern match (`sisterProjectInlineLine`) over
   every `<li>`/`<p>`'s whole rendered text (via `elementText`, which excludes inlined
   `<style>`/`<script>` first) for the sister-project "-inline" template family that renders
   with no wrapping box element (M3.3b).
6. `.mw-editsection` — edit-section links (defensive; never present in Parsoid REST HTML).
7. `selectorCitationLikeSup` (`sup[typeof*="mw:Extension/ref"]`, `sup.Inline-Template`,
   `sup[typeof="mw:Transclusion"]`) — citation superscripts, the maintenance-template family,
   and the `{{rp}}` page-locator template (M3.9, widened post-M4.1 from the original
   `selectorCitationSup`, which only covered the first).
8. `.mw-references-wrap, [typeof*="mw:Extension/references"]`, removing the closest
   `<section>` ancestor if present — whole reference-list sections, so no empty
   "References"/"Notes" heading survives on its own (superseded by `dropEmptyHeadings` as a
   general backstop, see below, but this is the primary removal).
9. `table.metadata, table.ambox` — metadata/maintenance tables (content `table.wikitable`
   is never matched).
10. `selectorFilePrefix, selectorMathExtension` (`[typeof^="mw:File"]`,
    `[typeof="mw:Extension/math"]`) then a final bare `img` sweep — whatever `renderImages`/
    `renderMath` didn't already replace with a placeholder.

Link stripping (`links.go`): every `<a>` unwrapped to its inner content, run after chrome
removal so only prose/table-cell links remain to unwrap.

Cleanup (`cmd/wikispike/cleanup.go`'s `cleanupMarkdown`, in order, fence-aware throughout so
M3.4's ASCII-art math is never touched by a whole-string pass):

1. `cleanupProse` per non-fenced chunk: empty/whitespace-only `()`/`[]` removal, then
   `dropUnmatchedClosers` for each of `()`/`[]` independently (asymmetric, closers only,
   D107), then per-line whitespace/space-before-punctuation collapse, empty list item
   removal, 3+ blank-line collapse.
2. `dropEmptyHeadings`, run once over the whole reassembled document (heading structure is
   document-wide, not chunk-local) — repeats to a fixed point, dropping any heading with no
   non-blank content before the next same-or-higher-level heading or EOF (M3.7).
3. A second fence-aware blank-run collapse, since dropping a heading can create a fresh 3+
   blank-run at its former position.

Pre-strip substitution stages (run before `stripChrome`, so their target markup is replaced
rather than deleted): `renderMath` (`math.go`, S6a) and `renderImages` (`images.go`, S6a).
